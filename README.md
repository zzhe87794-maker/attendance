# Simple Attendance by Seat Id

Elements of Computer Programming II, Lab 1. This is an Ant Java Web application for Java 11 and Tomcat 9, using `javax.servlet`, plain HTML, and no database, Spring, Maven, or JavaScript.

`src/java/attendance/Attend.java`, `web/index.html`, and `web/WEB-INF/web.xml` were transcribed from the supplied Chinese lab tutorial. The servlet deliberately retains the tutorial's synchronized, static `HashMap<String,String>` named `sid2seat`; its list is not sorted.

## Build and run on this computer

From PowerShell in `D:\AttendanceLab`:

```powershell
. .\attendance\scripts\env.ps1
cd attendance
ant dist
```

Outputs: `dist/attendance.war` and `attendance.war`. The latter is intentionally included in version control because the tutorial's Dockerfile deploys a prebuilt WAR.

The project includes NetBeans Java Web project metadata and an explicit Ant build script. Open the `attendance` folder using File > Open Project. Register the installed Tomcat 9 in Services > Servers and Java 11 in Tools > Java Platforms as necessary. The build script is maintained in this repository, rather than generated by an IDE session.

For another computer, install a Java 11 JDK and Ant, set `JAVA_HOME` and `CATALINA_HOME`, and run `ant dist`. Alternatively pass `ant -Dtomcat.home=C:/path/to/tomcat9 dist`.

Local Tomcat is configured on port 80 with `conf/Catalina/localhost/attendance.xml` pointing to `D:/AttendanceLab/attendance/build/web` as specified by the tutorial.

```powershell
# Run these from D:\AttendanceLab
.\attendance\scripts\start-tomcat.ps1
.\attendance\scripts\test.ps1
.\attendance\scripts\stop-tomcat.ps1
```

Open http://localhost/attendance/ . Start only one copy of Tomcat. The scripts set process-local environment variables; they do not change global Windows settings.

## Render deployment

Repository root must contain `Dockerfile`, `entrypoint.sh`, `attendance.war`, and `deploy-root/index.html`. Choose Docker runtime, branch `main`, Free instance, and the teacher-required service name `attend` followed by the actual last five digits of the student's ID. Never use an example student ID as the service name.

The application remains at `/attendance/`, exactly as in the tutorial Dockerfile. A minimal root landing page redirects to `/attendance/` so the root service URL requested by the assignment also works. The entrypoint adapts Tomcat's connector to Render's `PORT`. Shell files must use LF line endings.

After Render reports Live, verify the actual displayed URL in a browser, submit a test pair, check Attendee List, and submit a blank ID. No Render URL is considered a completed assignment answer until those checks pass.

Docker Desktop is optional and is not required for the local Tomcat tests. If installed:

```text
docker build -t attendance .
docker run --rm -p 8080:8080 attendance
```

## Expected behavior and limitations

- No `studentId` parameter: display all entries or `No sign-in record yet.`
- Nonblank ID: trim ID and seat, store the pair, and display confirmation.
- Blank/whitespace ID: display `Student Id can not be blank` and do not insert it.
- Resubmitting the same ID replaces its previous seat. Missing or blank seats are accepted.
- `HashMap` iteration is unspecified. To answer Question 3 without changing the tutorial behavior, propose iterating over `new java.util.TreeMap<String,String>(sid2seat).entrySet()` inside the existing synchronized block. String order is suitable for equal-length IDs and preserves leading zeros.
- Records exist only in server memory. Restarting or redeploying clears them.
- There is no authentication, instructor-only list, roster/seat validation, class session separation, timestamp, or persistent audit history.
- The tutorial writes user input directly into HTML. Consequently this teaching implementation also lacks HTML escaping and must not be used as a production attendance system.

Build and HTTP test evidence are stored outside the public repository in `D:\AttendanceLab\notes`. No real student IDs or test attendance records are embedded in the WAR.
